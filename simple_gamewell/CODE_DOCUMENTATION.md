# Code documentation — Simple GameWell ML analysis

## 1. What this project is

This is a small, self-contained analysis project. It answers a simple
predictive question:

> How well can prior valence, recorded linked-console play, and interval
> duration predict later affective valence?

The project contains:

```text
simple_gamewell/
├── analyze.py                     ← the Python program
├── CODE_DOCUMENTATION.md          ← this document
├── README.md
├── requirements.txt
├── data/
│   ├── gamewell_daily_intervals.csv.gz
│   ├── data_dictionary.csv
│   ├── DATASET_NOTES.md
│   └── clean/
│       ├── survey_daily.csv.gz
│       ├── survey_intake.csv.gz
│       ├── xbox.csv.gz
│       └── nintendo.csv.gz
└── outputs/                       ← generated by analyze.py
    ├── cohort_flow.csv
    ├── descriptives.csv
    ├── model_metrics.csv
    ├── feature_importance.csv
    ├── linear_coefficients.csv
    ├── summary.md
    └── figures/
        ├── fig1_cohort_flow.png
        ├── fig2_exposure_distribution.png
        ├── fig3_exposure_vs_valence.png
        ├── fig4_model_comparison.png
        ├── fig5_actual_vs_predicted.png
        ├── fig6_feature_importance.png
        └── fig7_residuals.png
```

The program uses:

- **pandas** — loading and preparing the data;
- **scikit-learn** — the predictive models;
- **matplotlib** — the graphs.

The program does **not** modify the data file. It writes only aggregate
results. Participant identifiers are never printed.

## 2. How to run it

From the repository root:

```powershell
.\.venv\Scripts\python.exe simple_gamewell\analyze.py
```

Or from inside `simple_gamewell`:

```powershell
..\.venv\Scripts\python.exe analyze.py
```

If the environment is missing packages:

```powershell
.\.venv\Scripts\python.exe -m pip install -r simple_gamewell\requirements.txt
```

The expected console output is an aggregate summary followed by a list of
model scores and the most important predictors. All files are written under
`simple_gamewell\outputs\`.

## 3. Data

### 3.1 The analysis-ready database

`data/gamewell_daily_intervals.csv.gz` is the cleaned daily interval
database. Each row is one interval between two consecutive cleaned daily
survey responses for one participant.

The file has 15,062 interval rows and 25 columns. The columns are described
in `data/data_dictionary.csv`; the build notes are in
`data/DATASET_NOTES.md`.

Key variables:

| Column | Meaning |
|---|---|
| `participant_id` | Participant identifier |
| `interval_duration_hours` | Time between the two survey completions |
| `prior_affective_valence` | Valence at the earlier survey |
| `later_affective_valence` | Valence at the later survey |
| `xbox_linked` | Whether Xbox is linked |
| `nintendo_linked` | Whether Nintendo is linked |
| `recorded_linked_console_minutes_unique` | Recorded linked-console minutes in the interval, counting simultaneous Xbox/Nintendo minutes once |

The four cleaned source tables used to build this database are included under
`data/clean/`:

| File | Contents |
|---|---|
| `clean/survey_daily.csv.gz` | Cleaned daily survey responses |
| `clean/survey_intake.csv.gz` | Cleaned intake survey responses |
| `clean/xbox.csv.gz` | Cleaned Xbox session records |
| `clean/nintendo.csv.gz` | Cleaned Nintendo session records |

They are included for provenance so the data behind the interval database is
available. `analyze.py` reads only `data/gamewell_daily_intervals.csv.gz`; it
does not need the four source tables at runtime.

### 3.2 Cohort rule

`load_and_prepare()` keeps an interval only if all of the following are true:

1. Xbox and/or Nintendo is linked;
2. `interval_duration_hours` is greater than 0 and at most 48;
3. `prior_affective_valence` and `later_affective_valence` are both present;
4. `recorded_linked_console_minutes_unique` is present.

Missing linkage or exposure is never treated as zero.

Cohort flow from the real run:

| Stage | Intervals | Participants |
|---|---:|---:|
| All intervals in file | 15,062 | 1,104 |
| Linked Xbox and/or Nintendo | 5,904 | 419 |
| Valence at both endpoints | 5,774 | 406 |
| Duration 0–48 hours | 5,076 | 371 |
| Exposure non-missing (analysis cohort) | 5,076 | 371 |

The final cohort has **5,076 intervals from 371 participants**. Of those
participants, **171** have more than one distinct exposure value.

### 3.3 Derived variables

For each interval:

```text
exposure_hours    = recorded_linked_console_minutes_unique / 60
exposure_between  = participant mean of exposure_hours
exposure_within   = exposure_hours - exposure_between
```

`exposure_within` answers: “Was this interval above or below this person’s
own usual amount of recorded play?”

`exposure_between` answers: “Does this person usually play more or less than
other people?”

The model uses both so that within-person and between-person differences are
not conflated.

## 4. Models

The program compares three models.

### 4.1 Mean baseline

```python
DummyRegressor(strategy="mean")
```

This predicts the training-set mean later valence for every interval. It is a
sanity check: a useful model should beat it.

### 4.2 Linear regression

```python
LinearRegression()
```

The model is:

```text
later_valence ~ prior_valence
               + exposure_within
               + exposure_between
               + duration_hours
```

The coefficient on `exposure_within` is the estimated difference in later
valence associated with a one-hour increase in a person’s interval exposure
relative to their own mean, holding the other predictors fixed.

### 4.3 Random forest

```python
RandomForestRegressor(
    n_estimators=400,
    min_samples_leaf=5,
    random_state=42,
    n_jobs=-1,
)
```

A random forest is a collection of decision trees. Each tree learns a
non-linear prediction rule, and the forest averages their predictions. It can
capture interactions and curved relationships that linear regression cannot.
It is used here as a flexible predictive benchmark, not as a causal model.

### 4.4 Train/test split

`GroupShuffleSplit` splits **participants**, not rows:

- 80% of participants for training;
- 20% of participants for testing;
- random seed 42.

This prevents the same participant appearing in both sets, which would make
the test score too optimistic.

Real split:

| Quantity | Value |
|---|---:|
| Training intervals | 4,016 |
| Test intervals | 1,060 |
| Training participants | 296 |
| Test participants | 75 |

### 4.5 Metrics

For each model:

- **R²** — proportion of outcome variance explained; higher is better, and
  negative values mean the model is worse than predicting the mean.
- **MAE** — mean absolute error in valence points; lower is better.
- **RMSE** — root mean squared error; lower is better and penalises large
  errors more strongly.

## 5. Function-by-function explanation

### `as_linked(series)`

Converts a linkage column to true/false.

- Accepts `true`, `1`, `yes`, `y`, `t` in any capitalization.
- Missing or unrecognised values become `False`.
- This is an encoding helper, not a statistical transformation.

### `load_and_prepare()`

- Reads the gzipped CSV with pandas.
- Checks that the required columns exist.
- Applies the cohort rule.
- Builds the cohort-flow table.
- Creates `exposure_between` and `exposure_within`.
- Returns `(cohort, flow)`.

### `make_descriptives(cohort)`

Produces aggregate descriptive statistics:

- interval and participant counts;
- exposure mean, SD, median, and zero-play percentage;
- prior and later valence means and SDs;
- within-person valence SD;
- within-person exposure SD;
- intervals per participant.

No participant-level rows are written.

### `fit_models(cohort)`

- Builds the feature matrix and outcome vector.
- Splits by participant.
- Fits the mean baseline, linear regression, and random forest.
- Computes train and test R², MAE, and RMSE.
- Computes permutation importance for the random forest.
- Extracts linear-regression coefficients.
- Returns the metrics table, importance table, coefficient table, and a
  context dictionary used for the figures.

### `save(fig, name)`

Tightens the figure layout, saves it at 160 dpi, and closes it.

### `make_figures(...)`

Creates the seven figures described in Section 6.

### `write_summary(...)`

Writes `outputs/summary.md`, a short plain-language report containing the
cohort flow, descriptive table, model comparison, feature importance, and
the main caveat.

### `main()`

Runs the full pipeline in order:

1. create output folders;
2. load and prepare the cohort;
3. compute descriptives;
4. fit the models;
5. write CSV tables;
6. create figures;
7. write the Markdown summary;
8. print an aggregate console summary.

### 7.1 Cohort

```text

371 participants
```

### 7.2 Descriptive statistics

| Measure | Value |
|---|---:|
| Median interval duration | 24.4265 hours |
| Mean exposure | 1.2020 hours |
| Exposure SD | 2.6686 hours |
| Median exposure | 0 hours |
| Prior valence mean | 68.5971 |
| Later valence mean | 68.8865 |
| Within-person valence SD | 12.0559 points |
| Within-person exposure SD | 1.6651 hours |

### 7.3 Model comparison

| Model | Train R² | Test R² | Test MAE | Test RMSE |
|---|---:|---:|---:|---:|
| Mean baseline | 0.0000 | −0.0730 | 18.1896 | 22.5518 |
| **Linear regression** | **0.5580** | **0.4913** | **11.1399** | **15.5282** |
| Random forest | 0.7451 | 0.4838 | 11.2104 | 15.6414 |

The linear regression has the best test R² (0.491) and the lowest test MAE
(11.14 valence points). The random forest fits the training data much better
(train R² 0.745) but does not generalise better to the test participants.
This is a useful lesson: a more complex model is not automatically better.

### 7.4 Most important predictors

Random-forest permutation importance, measured as the increase in test MAE
when a feature is shuffled:

| Feature | Importance | SD |
|---|---:|---:|
| Prior valence | 9.9588 | 0.3261 |
| Interval duration | 0.1785 | 0.0960 |
| Exposure: person average | 0.1467 | 0.0946 |
| Exposure: within person | 0.1008 | 0.0626 |

Prior valence dominates. The exposure variables add very little predictive
information.

Linear-regression coefficients:

| Feature | Coefficient |
|---|---:|
| Prior valence | 0.7475 |
| Exposure: within person | −0.0757 |
| Exposure: between person | −0.0145 |
| Interval duration | 0.0693 |

The within-person coefficient is small and negative in this predictive
specification. It should not be interpreted as a causal effect.

## 9. Limitations

1. **Predictive, not causal.** The models describe associations and
   prediction. They do not show that gaming changes mood.
2. **Recorded linked-console play only.** The exposure measure does not
   include Steam, mobile, or unlinked-platform play.
3. **Zero is not proof of no play.** A zero means no intersecting cleaned
   session under the study’s coverage assumption. Missing capture cannot be
   distinguished from genuine no-play.
4. **Nintendo coverage is partial.** Nintendo telemetry covers first-party
   titles only.
5. **Observational cohort.** Participants are those with linked Xbox and/or
   Nintendo accounts and usable intervals. Results may not generalise.
6. **Single train/test split.** The metrics come from one participant-level
   split with a fixed seed. A different split would give somewhat different
   numbers. Cross-validation would give a more stable estimate.
7. **Random forest is not interpretable as a causal model.** Permutation
   importance describes predictive reliance, not a causal effect.
8. **Prior valence is very strong.** Because prior valence predicts later
   valence well, the model’s R² is dominated by it. The exposure coefficients
   should be read separately.
